# キャンペーンを開始 {#launch-campaign}

キャンペーンの開始とは、キャンペーンをドラフトからアクティブな送信に移動するアクションです。 ローンチダイアログが開く前に、Haloはキャンペーンの準備ができているかどうかを確認し、必要な設定が完了するまでローンチをブロックします。 ローンチダイアログには、メールとオーディエンスのプレビューが表示され、ユーザーは送信スケジュールをインラインでレビューまたは変更し、ローンチが成功したかどうかを報告できます。 この節では、エンドツーエンドのローンチ体験について説明します。ローンチ中に提供されるスケジュールオプションについては、[ キャンペーンのスケジュール ](/help/coworker/campaigns/schedule-campaign.md)を参照してください。

## 前提条件

- キャンペーンはドラフトステータスである必要があります。<!-- The Launch action isn't available once a campaign is already live. -->
<!-- - The campaign must pass a readiness check: sending settings configured, at least one test email sent, and a real (non-sample) audience uploaded. -->
- [NEEDS INPUT — エンジニアに確認するには、一部のユーザーに、実際のローンチボタンではなく「近日公開予定」エクスペリエンスが表示される場合があります。このボタンでは、アプリ内でローンチするのではなく、キャンペーンのダウンロードやプルーフメールの送信のみを提供します。 特定のユーザーまたはキャンペーンがどのエクスペリエンスを受け取るかを決定する要素を確認します。]

## この機能の機能

ユーザーがキャンペーンを開始すると、Haloはまずキャンペーンの準備ができていることを検証します。 必要な項目が見つからない場合は、起動を続行する前に修正する必要がある項目がダイアログに表示されます。 検証が完了すると、ローンチダイアログに電子メールとオーディエンス/ワークフローのプレビューが表示され、ユーザーはフローを離れることなく送信スケジュールをレビューまたは編集できます。また、大量の送信の場合は、推定送信量の通知が表示されます。 ローンチのトリガーを確認すると、Haloは、ローンチ、既にローンチ、または失敗という3つの結果のうちの1つを報告します。

### 主な行動

- Launchは、ドラフトステータスのキャンペーンでのみ使用できます。既にライブになっているキャンペーンを再度起動することはできません。
- 起動ダイアログが開く前に、準備状況チェックが自動的に実行されます。 未解決の問題は起動をブロックし、各問題を解決する方法が表示されます。
- 起動ダイアログには、電子メールのプレビュー（件名、プリヘッダー、送信者）とオーディエンス/ワークフローのプレビューが表示されます。
- 送信スケジュールは、ローンチダイアログ内から確認または変更できます。
- 大量の送信の場合、このダイアログには送信量の推定インパクトが表示されます。 [NEEDS INPUT – この通知の正確な文言はコード ]から入手できませんでした
- 成功すると、キャンペーンのステータスが「スケジュール済み」または「ライブ」に更新され（選択したスケジュールに応じて）、確認メッセージに2時間以内にキャンペーンインサイトが利用できるようになります。
- キャンペーンが既に開始されている場合（例えば、重複クリックから）、Haloはエラーではなく「既に開始された」メッセージを表示します。
- 起動に失敗すると、エラーメッセージが表示され、キャンペーンはドラフトに残ります。ユーザーは再試行できます。
- キャンペーンを停止<!--(see [Stop a live campaign](./stop-live-campaign.md))-->すると、同じキャンペーンレコードから再開できません。停止は、別の永続的な状態になります。

## アクセス方法

**キャンペーンを開始するには：**

1. キャンペーンから、**Launch**&#x200B;をクリックします（「準備完了」と表示されます）。
2. 何か見つからない場合は、「まだ注意が必要な点がいくつかあります」というタイトルのダイアログに、次の項目が表示されます。
   - **メール設定の設定** – 送信パラメーター（送信者/ドメイン）がまだ設定されていません。
   - **電子メールがテストされていません** – 少なくとも1通の電子メールを送信して、電子メールを起動する前にプルーフします。
   - **開始に必要な実在オーディエンス** — キャンペーンはまだサンプル オーディエンスを使用しています。実在オーディエンス CSVをアップロードしてください。
     各項目を解決してから、もう一度起動してみてください。
3. キャンペーンが準備状況チェックに合格すると、起動ダイアログが開き、メールとオーディエンスのプレビューが表示されます。
4. ダイアログに表示されているスケジュールを確認します。 変更するには、[ キャンペーンの起動時にスケジュール ](/help/coworker/campaigns/schedule-campaign.md)で説明されているスケジュール オプションを使用してから保存します。
5. ローンチを確認します。 成功すると、確認メッセージが表示され、キャンペーンのステータスが更新されます（「スケジュール済み」または「ライブ」に）。

## この機能で実行できない処理

- サンプル（実例ではない）オーディエンス、テストされていない電子メール、未設定の送信設定などを使用してキャンペーンを開始することはできません。この3つの設定をすべて最初に解決する必要があります。
- ローンチでは、同じアクションの一部としてスケジュールを受け付けません。スケジュールは、ローンチの確認前またはローンチの一部として（同じダイアログ内から）個別に保存されます。
- 停止されたキャンペーンの再開はサポートされていません。停止は永続的な<!--(see [Stop a live campaign](./stop-live-campaign.md))-->です。
- [NEEDS INPUT — エンジニア/PMと確認するため：一部のユーザーでは、Launchは、キャンペーンダウンロード（PDF/DOCX）またはプルーフメール送信のみを提供する「近日リリース予定」エクスペリエンスに置き換わる場合があります。アプリ内セルフサービスのローンチは行われません。 このコホートのハウツー手順が変更されるので、公開前に適用されるオーディエンスを確認してください。]
